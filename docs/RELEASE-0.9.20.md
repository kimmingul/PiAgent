# PiAgent 0.9.20 — OMP 작업 상태와 대화 계속하기

**한국어** · [English](RELEASE-0.9.20.en.md) · [문서](README.md)

2026-10-09 사전 릴리즈. [서명 설치파일과 SHA-256](https://github.com/kimmingul/PiAgent/releases/tag/v0.9.20).

긴 작업에서 개별 모델 응답이 취소된 뒤 OMP가 작업을 계속해도 PiAgent가 먼저 “중지”를 표시하던
문제를 수정했습니다. native OMP는 `session_settled` 또는 전체 종료를 확인한 `prompt_result`까지
작업 소유권을 유지합니다. 개별 `message_end`의 `aborted`, `agent_end`, 종료되지 않은
`prompt_result`는 전체 작업 종료로 취급하지 않습니다. 이후 답변과 도구 이벤트를 계속 처리하며,
사용자 중지 요청과 프로세스 장애 처리는 유지됩니다.

OMP가 비동기 후속 작업을 시작해 일반 prompt를 거절하는 경우, 확인된 busy 거절만 후속 대기열에
한 번 보냅니다. 실행 중인 프로세스를 종료하지 않습니다. 대기열 등록도 실패하면 안내를 표시하고
진행 중인 작업의 상태와 중지 버튼을 유지합니다. 타임아웃이나 원인 불명의 거절은 자동 재전송하지
않습니다. 모호한 요청을 중복 실행하지 않기 위한 기존 처리입니다.

PiAgent가 질문·승인 요청을 임의로 5분 뒤 취소하던 타이머를 제거했습니다. OMP가 질문의 시간 제한과
취소를 관리하고 PiAgent는 OMP의 `cancel`을 반영합니다. 사용자 답변이나 승인을 자동 선택하지
않습니다. 닫힌 질문에는 시간 만료 또는 취소 가능성을 안내합니다.

prompt 거절은 실행 중, 컨텍스트 초과, 인증 필요, 제공자 한도 등 확인 가능한 범주로 안내합니다.
진단 로그에는 범주만 기록하고 원래 제공자 오류·키·인증 주소를 그대로 노출하지 않습니다.
알 수 없는 오류는 일반 오류로 남으며, 이 릴리즈가 과거에 버려진 오류 원문을 복구하지는 않습니다.
실패한 자동 압축을 “압축 완료”로 표시하는 경우도 수정했습니다.

동시 세션 조회 중 Windows가 `session.json` 파일 교체를 일시적으로 거부하던 저장 실패도 보완했습니다.
세션 잠금과 기존 파일을 유지한 채 해당 Windows 공유 오류만 짧게 재시도합니다. 대상 파일을 지우고
다시 쓰는 방식은 사용하지 않으며, 재시도 한도를 넘으면 실패를 보고합니다.

파일 변경의 복원 기록 제한은 기존과 같습니다: 기존 Git 추적 UTF-8 파일, 파일당 32 KiB,
한 응답의 변경 파일 최대 8개, 변경 전후 합계 최대 256 KiB입니다. 제한을 넘으면 전체 복원 기록을
만들지 못했다는 안내를 표시합니다. 실제 파일 변경은 유지되고 이 안내는 작업 중단을 뜻하지 않습니다.
일부 파일만 저장한 기록을 전체 복원 기록으로 표시하지 않습니다. 많은 파일을 변경한 작업은 Git diff로
검토하고 Git으로 보존하세요. 새 파일·삭제·바이너리·IDE 미저장 버퍼는 이 기록의 대상이 아닙니다.

한국어·영어 안내를 함께 제공합니다. 모델 답변과 외부 도구 결과는 자동 번역하지 않습니다.
RAD Studio 지원 버전 및 폼 디자이너 범위는 [0.9.18](RELEASE-0.9.18.md),
언어 설정은 [0.9.19](RELEASE-0.9.19.md)와 같습니다.

기존 대화 JSONL과 메시지 스냅샷을 보존했습니다. 이번 검증은 별도 테스트 작업영역과 OMP 대체
프로세스로 수행하며, 사용자가 실행 중인 개발 작업을 중지하거나 프로젝트를 변경하지 않습니다.
설치파일을 새로 내려받아 선택한 IDE를 모두 닫고 설치한 뒤 PiAgent를 다시 연결하세요.
업데이트를 게시하는 것만으로 실행 중인 Core/IDE가 교체되지는 않습니다.

전체 회귀 테스트 **155/155**, C#/Delphi 어댑터 통합 **17/17**을 통과했습니다.
동시 세션 복구 스트레스 검증은 별도 실행 **20/20**을 통과했습니다. 개별 응답 취소 뒤 계속하기,
실행 중 거절과 대기열 실패, 질문 대기·취소, 파일 수·크기 제한, 파일·Git 상태 보존을 검증했습니다.
서명과 설치 payload 검증 결과는 릴리즈의 Validation 항목에 추가합니다. 모든 제공자 계정으로 새 장시간 작업을 실행하거나
VS2022·RAD32의 실사용 검증을 새로 완료했다고 주장하지 않습니다.
